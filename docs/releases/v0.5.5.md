# 滚猫md v0.5.5

v0.5.5 为 Windows 和 Android 版增加搜索自动定位与全部命中高亮，并包含保存、网页粘贴及图片导出的可靠性修复。

本次发布 Windows 便携版 EXE、Android ARM64 APK 与 SHA-256 校验文件。Android 已补充更新至 v0.5.5 / 5005，沿用旧版签名，可覆盖安装；同时包含 v0.5.3–v0.5.4 的阅读位置和源码显示修复。

## 更新内容

- **自动定位与全部高亮**：输入搜索词后自动跳到第一个结果；只有一个结果时直接定位该处，有多个结果时高亮全部命中的原文。当前结果使用更深的底色和下划线，输入框保持焦点，支持上一项、下一项和循环查找。
- **覆盖三种视图与大文档**：普通文档的所见即所得、源码和阅读视图均支持；大文档仅绘制可视区高亮，继续保留分块渲染。编辑、撤销或替换后刷新结果，清空或关闭查找后清除高亮。
- **查找面板布局**：面板在正文上方单独占位，文首结果在桌面和窄屏上均可见。旧 WebView 的阅读视图支持高亮回退。
- **保存与关闭保护**：保存后等待本地记录写入期间出现新编辑或异步粘贴时，保留当前文档供再次确认；重复关闭请求、草稿写入失败和关闭失败后重试保持一致，旧对话框的延迟关闭事件不会误关新提示。
- **长文件名保存**：原子保存使用独立的短临时文件名，避免合法的长文件名因附加临时后缀而超过文件系统名称上限。
- **网页代码粘贴**：保留代码块中的连续空行、缩进和仅包含空白的行。
- **图片导出边界**：修复 Markdown 代码围栏与原始 HTML 块之间的状态判断，正确处理代码中的 HTML 示例及带尾随文字的围栏样式代码行。

## English

v0.5.5 adds automatic search navigation and persistent highlighting to the Windows and Android apps. Entering a search term jumps to the first result and highlights every match, with a stronger background and underline for the current result. Input focus is preserved, and previous/next navigation wraps through the results. Clearing or closing Find removes the highlights; edits, undo and replacements refresh them.

All three views and large documents are supported. Large documents decorate only the visible viewport. The Find panel reserves space above the document so results at the beginning remain visible on desktop and narrow screens. Reader mode includes a fallback for WebViews without CSS Highlight support.

Additional fixes protect newer edits while local records are flushed before leaving a document, handle repeated close requests and failure retries, save files with names near the filesystem limit, preserve blank and whitespace-only lines in pasted code blocks, and correct code-fence/raw-HTML boundaries during image export.

This release ships the **Windows v0.5.5 portable EXE**, **Android v0.5.5 / 5005 ARM64 APK**, APK v4 signature sidecar, and SHA-256 files. Both builds use release commit `d6687d8`. Android retains the existing signing certificate for in-place upgrades and also includes the reading-position and source-display fixes from v0.5.3–v0.5.4.

Validation on 2026-10-13 passed 261 JavaScript tests, 17 Rust tests, 208 search browser checks, 30 additional search edge checks, 8 paste/save race scenarios, 13 TextPack/recovery checks, 43 reading-position checks, and 10 startup Help/settings checks. The TextPack suite produced one expected injected save-failure alert; the other suites reported no unexpected page errors or dialogs.

The frontend and Windows production builds succeeded, with bundle-size and dynamic-import warnings. The Rust release build took 2 minutes 53 seconds and the frontend build took 3.23 seconds. The EXE reports file/product version 0.5.5, is 6,654,976 bytes, and contains all four hashed CSS/JavaScript asset names from this build. Its SHA-256 is recorded above.

Android validation additionally passed 20 relevant Node tests, 5 platform browser checks, and 241 framework/policy cases against each of the source and final merged manifests. The signed APK is 11,154,875 bytes, targets ARM64 with minSdk 24 / targetSdk 36, and reports version `0.5.5 / 5005`. Its v2/v3/v4 signatures verify with the v0.5.2 certificate, and 16 KiB ZIP alignment passes. All 15 packaged launcher PNGs, both adaptive icons, and Manifest references match the source resources. The packaged native library matches the current Rust release build and contains all four frontend asset names.

The Android frontend and Rust builds took 3.25 seconds and 1 minute 01 seconds. A local Windows symlink restriction then interrupted `npm run dist:android`; copying the freshly built native library into `jniLibs` and running Gradle assembly with the Rust task excluded completed packaging in 2 minutes 21 seconds. SDK XML version and Gradle deprecation warnings remain. The APK SHA-256 is recorded above; the combined checksum manifest also includes the unchanged Windows EXE and APK signature sidecar.

Browser checks use isolated Edge with mocked file, window-close, and native interfaces. The Reader fallback was tested by disabling Edge's `Highlight` constructor. Native Windows WebView UI, actual older WebViews, and Android devices remain unverified.
