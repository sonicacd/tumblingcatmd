# 滚猫md v0.5.4

v0.5.4 改善 Windows 版源码视图的标题与语法标记显示。标题采用正文的字号、字重和行高，`#`、`===`、`**` 等标记在三种主题下更清晰，便于直接编辑 Markdown。

本次发布 Windows 便携版 EXE 与 SHA-256 校验文件。Android APK 继续使用 [v0.5.2](https://github.com/sonicacd/tumblingcatmd/releases/tag/v0.5.2)，本次未重新构建，尚未包含此修复。

## 修复内容

- **源码标题排版**：普通文档源码区的各级标题使用正文的字号、字重和行高，包含文字下方的 Setext 标题标记，避免长段落被放大加粗后难以辨认源码。
- **语法标记可见性**：源码标记使用当前主题的文字颜色变量，提高护眼、纯白、纯黑主题中的可见性。
- **保留原文**：保留 `# 标题` 和文字下一行使用 `===` 等原有标题写法。`===` 表示一级标题，标记可直接编辑；此次调整只改变显示样式。

## English

v0.5.4 improves the appearance of headings and syntax markers in the Windows Source view. Headings inherit the body font size, weight, and line height, including Setext underline markers. Syntax markers such as `#`, `===`, and `**` use the current theme's text colors for clearer editing in Eye Care, White, and Black themes.

The document retains its original Markdown text and heading syntax. Both `# Heading` and text followed by an `===` line remain directly editable; this release changes their source display styles.

This release ships the **Windows v0.5.4 portable EXE**, **SHA256SUMS.txt**, and **rollcat-md.exe.sha256**. Android continues to use the [v0.5.2 APK](https://github.com/sonicacd/tumblingcatmd/releases/tag/v0.5.2); it was not rebuilt and does not include this fix.

Validation on 2026-09-17 passed 246 JavaScript tests, 16 Rust tests, and 43 reading-position checks. The frontend production build succeeded. A temporary source-view check matrix under `work/qa` passed 20 checks covering 1440px/390px layouts, three themes, source preservation across all three views, and viewport rendering for large documents. A separate narrow-screen verification passed two deletion/undo checks.

The Windows production build succeeded, with existing bundle-size and dynamic-import warnings. The Rust release build took 4 minutes 13 seconds, and the frontend build took 4.07 seconds. The EXE reports file/product version 0.5.4 and is 6,655,488 bytes. The built CSS contains the source-heading fix, and all four hashed CSS/JavaScript asset names from this build were verified in the EXE. Its SHA-256 is recorded above.

Browser checks use isolated Edge with mocked file/native interfaces. Native Windows WebView UI and Android device behavior remain unverified.
